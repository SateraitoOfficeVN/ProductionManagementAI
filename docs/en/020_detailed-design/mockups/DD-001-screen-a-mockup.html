Production order create / edit

Rendered states for Screen A, drawn in the app's existing look (Tailwind gray palette and system font from the login page). Numbers in the captions point to BD-001 §3 items, V- rules, E- events and MSG- message IDs in DD-001. The sample data is illustrative.

  • Order no. PO-YYYY-NNNNN
  • Plant time Asia/Tokyo
  • 30 seeded products
  • PC ≥ 640px · SP < 640px
1 Create — empty 2 Product list open 3 Validation errors 4 Created → edit (Draft) 5 In progress — locked 6 Completed — terminal 7 Stale save (409) 8 Discard changes? 9 Not found 10 SP — create 11 SP — locked

Read-only fields (product and quantity after Draft) are drawn with a dashed border and gray fill. They stay focusable and are announced as read-only, not disabled. Focus rings are 2px gray-900 with a 2px white offset. Status options come from the API's allowedNextStatuses, so the UI never offers a transition the server would reject.
